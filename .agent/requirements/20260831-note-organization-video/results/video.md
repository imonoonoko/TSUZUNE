# V1 — 動画から抽出した整理原則

Source: https://www.youtube.com/watch?v=PGPMocgdIiA

## 確認できた主張

- AIが利用者を理解しにくい主因を、プロンプト不足よりも「必要な文脈が毎回届かないこと」と捉える。
- 文脈は特定AIサービスへ閉じ込めず、Markdownを中心とする持ち運べる知識資産として保持する。
- 文脈基盤には、AIからの到達性、低摩擦な捕捉、Rawのままにしない整理、読む順を示す目次が必要である。
- 例示された役割は Inbox / Projects / Ideas / Resources / Context / imported data / Processed である。
- AIは原文を削除せず、処理済みであることと配置先を残す。
- ノートは短く責務ごとに分け、AIには目次から必要な部分だけ読ませる。
- MCPと意味検索を、複数AIからローカル文脈へ到達する手段として使う。

## TSUZUNEへ採用する部分

- Markdown正本、入口インデックス、原典と再利用知識の分離、原子化、必要部分だけを読む方針。
- AIによる意味検索は候補発見までとし、人間が採用した関係だけを明示Wikiリンクへする。
- 取り込みと整理を別段階にし、Rawをそのまま恒久的なAI文脈へ混ぜない。

## そのまま採用しない部分

- 動画のフォルダ名をTSUZUNEへ重複新設しない。現行の `01_受信箱`、`10_プロジェクト`、`20_分野`、`30_知識`、`40_情報源` が役割を既に持つ。
- 約1000件の一括移行、日次AI整理、週次クリーナーは作者の運用例であり、TSUZUNEの必要性を示す検証ではない。
- Processed/archive/history用の新フォルダは作らない。状態とMOCから退避し、旧 `50_履歴` は不活性のまま扱う。

## 証拠上の注意

動画内の効果は作者の自己報告を含む。大量移行や定期自動化は、現在のTSUZUNEで観測された必要性がない限り採用しない。
