# Obsidian Plugin Compatibility Platform Orchestration

## Goal

Raise compatibility without claiming an unverifiable all-ecosystem 100%. Every supported claim is bound to an exact plugin version and a complete public desktop behavior matrix.

## Packets

1. `current-host-audit`: current scanner, artifact verifier, iframe host, bridge, settings and acceptance reuse seams.
2. `official-api-contract`: current official public API, plugin lifecycle, desktop runtime and distribution constraints from primary sources.
3. `wave1-targets`: compare real plugin repositories by user value, API footprint, dependencies and feasibility of exact conformance.
4. `conformance-security`: define 100% denominator, fail-closed loading, capability profiles and unsafe boundaries.

## Integration Policy

- Parent owns Task Contract, target recommendation, all edits, tests, production update and TSUZUNE writes.
- Research packets are read-only. No agent may execute third-party plugin code, write the production Vault, install plugins, change Git state, or broaden scope.
- Shared runtime code is added only for APIs required by at least two accepted targets; otherwise keep a target adapter.
- Unmodified artifact execution and published behavior evidence outrank shim unit tests.

## Verification Order

Official source identity -> API footprint -> RED conformance -> smallest implementation -> focused GREEN -> full regression -> packaged Electron -> installed `app.asar` -> production receipt -> live user confirmation.

## Escalation

Return one decision packet to the user when Wave 1 choices materially trade user value against Node/network/filesystem risk, or when 100% published behavior requires an authority outside the current contract.
