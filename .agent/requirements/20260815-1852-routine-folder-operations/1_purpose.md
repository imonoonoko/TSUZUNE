# Purpose

## Outcome

TSUZUNEを日常の知識基盤として使う時、利用者とAIが現在のフォルダ構造を把握し、必要な場所にフォルダを一つ作り、単一ノートまたはフォルダを予測可能に移動・改名できるようにする。

目標は高度な自動整理ではない。シェルやエクスプローラーへ逃げず、失敗しても「どこまで成立したか分からない」状態を残さずに、一件ずつ整理できることである。

UIとAIは同じ移動実行経路を使う。差を許すのは入力と確認方法だけとし、Drive台帳、監査、競合検査、障害復旧を別実装にしない。

## Primary users and moments

- 利用者が新しいプロジェクト、知識領域、情報源区分を作る時。
- 利用者がファイルツリー上で、既存ノートやフォルダを手動整理する時。
- Codex等のAIが、格納先を確認して新規フォルダを作り、単一ノートの整理を提案・実行する時。
- フォルダ名や分類方針が変わり、配下を保ったまま改名・移動する時。

## Success conditions

1. 利用者またはAIが、本文を大量取得せずに現在の構造を確認し、既存親の直下へ一つのフォルダを作れる。
2. 単一ノートまたはフォルダを、衝突、リンク影響、保護領域、Drive影響を確認して移動・改名できる。
3. フォルダ移動でも、filesystem、Drive台帳、AI監査が一つの操作として成功するか、復旧可能な失敗として停止する。

## Safety boundary

- `50_履歴/**`は監査の信頼境界であり、AIだけでなくアプリUIからも移動、改名、ゴミ箱を禁止する。閲覧はできる。
- `40_情報源/**`は人間が意図して再分類できる。AIの本文変更は禁止を維持し、AIの移動先としての解禁は既存の別ゲートで判断する。
- Windows Explorer等によるVault外部からの直接操作までは防げない。常用上の保証範囲はTSUZUNEアプリとTSUZUNE MCPである。

## Non-goals

- AIによるVault全体の自動分類、バックグラウンド整理、複数項目一括移動。
- タグ・フォルダ同期ルール、smart folder、app-owned database。
- 任意フォルダごとの「AI不変」設定、アカウント、共同編集、クラウド権限管理。
- AIによる添付単体移動、trash、完全削除。
- この設計と同時にtrash復元まで実装すること。
