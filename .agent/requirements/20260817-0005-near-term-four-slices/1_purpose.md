# Purpose

## Outcome

直近の未完了4項目を、利用者データを危険に晒さない最小の製品境界で完了させる。

1. 左右サイドバーを、中央のノート状態を失わず折りたためる。
2. Drive同期の削除競合を、既定では保持しつつ、明示的に選んだ時だけ復旧可能なゴミ箱操作として伝播できる。
3. 本番分類候補5ノートを、fresh preflight、Drive上の一意性、巻き戻し条件が揃った場合だけ物理適用できる。
4. 今後作られるAI更新履歴を暗号学的に検証可能にし、既存164件は監査証跡として無変更で残す。

## Success conditions

- 4項目それぞれに、現在コードから失敗を検出する最小テストと、実装後の独立した確認結果がある。
- 削除、分類、履歴圧縮について、適用可能条件を満たさない本番変更は実行せず、停止理由と次の一手を機械可読な成果物に残す。
- 製品コードを変更した最終snapshotは、全体検証後に`npm run production:update`でこのPCへ導入・検証する。

## Safety boundary

- 本番Vaultを自動smoke testのfixtureとして開かない。
- TSUZUNE起動中を理由に強制終了しない。
- Drive削除伝播はopt-inであり、既定動作を`preserve`から変えない。
- 既存のAI更新履歴164件を、推測したrevision情報で検証済みにしない。
- 分類5件は、対象の内容・移動先・Drive identity・rollback preimageのいずれかが曖昧なら物理移動しない。
