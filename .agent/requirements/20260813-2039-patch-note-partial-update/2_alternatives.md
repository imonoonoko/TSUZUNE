# Alternatives — patch_note

| # | 案 | 内容 | 採用 |
|---|---|---|---|
| A | **現状維持 (update_note のみ)** | 部分更新は全文書き換えで続行 | ✗ — 本件の動機そのもの。20KB級ノートの無駄が残る |
| B | **update_note に部分更新モードを追加** | 既存ツールに `operations` パラメータを足す | ✗ — ツールの契約が二義的になる。既存クライアントの互換リスク。新ツール分離が安全 |
| C | **patch_note を新規ツールとして追加 (採用)** | `operations: [{find, replace, replace_all?}]`、原子的・revision必須・履歴記録 | ✅ — 契約が単一で明確、既存ツール無変更 |
| D | **セクション追記ツールのみ (append_to_section)** | 部分更新は追記限定 | ✗ — リンク修正・文言変更 (用途の大部分) をカバーできない |
| E | **find 一致は曖昧許容 (最初の1件)** | 複数一致時に自動で先頭を置換 | ✗ — 意図しない箇所を書き換える危険。一致は「ちょうど1件」を既定とし、`replace_all` で明示的全置換のみ許可 |
| F | **履歴を記録しない (update_note と揃える)** | 明示編集ファミリーと整合 | ✗ — 部分編集ほど監査が重要。ユーザー判断で「履歴を記録する (案A推奨)」に確定 (discussion_log 参照) |
| G | **行末は生バイト一致** | CRLF をそのまま find に要求 | ✗ — AI が `\r` を書く必要が生じ、実用上の罠。LF正規化照合 + 復元を採用 |
| H | **no-op を許可 (同一結果でも書き込み)** | 単純化 | ✗ — 無駄な書き込み・履歴汚染を防ぐため拒否する |
