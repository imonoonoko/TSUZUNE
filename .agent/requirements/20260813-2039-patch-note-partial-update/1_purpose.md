# Purpose — patch_note (部分更新ツール)

## 背景 (Problem)

`update_note` は **全文書き換え必須** の設計である。1行のリンク修正・単語の差し替えを行うためには:

1. `fetch` でノート全体を取得
2. 内容を全文コピーし、AI側で1箇所だけ変更
3. 全文を `update_note` で再送 (revision照合つき)

このため、20KB級のノートや、複数ノートへの小さな修正 (例: リネーム後のリンク更新3件) では、無関係な本文まで転送・検証・書き戻しが発生する。実測では本ボールトの整理作業 (A: 受信箱仕分け / B: 命名統一 / C: 役割分担) で合計 **10回以上** の全文書き換えを行った。

さらに、`update_note` は **履歴を記録しない** (履歴を記録するのは `autonomous_update_note` のみ)。部分編集ほど監査が重要な局面 (細かい修正の積み重ね) で監査が残らない。

## ゴール (Goal)

MCPツール `patch_note` を追加し、以下を満たす:

- **find/replace ベースの部分更新** を1コールで1〜20件実行できる
- **原子的**: 1件でも失敗したら全体を拒否し、何も書き込まない
- **安全**: revision照合・不変path拒否・reviewモードを既存writeツールと同等に維持
- **監査**: 変更内容を `autonomous_update_note` 方式で `50_履歴/AI更新` に記録する
- **実用性**: ボールトの実ファイルがCRLF行末でも、AIが LF で find を書ける (行末正規化照合 + 書き出し時復元)

## 非目標 (Non-Goals)

- UI への部分編集機能の追加は含まない (MCPスライスのみ)
- Graph・Context からの履歴除外は別スライス (20260813-2035 と同一方針)
- `update_note` 自体の挙動変更はしない (互換維持)
