# Discussion Log — patch_note

## 2026-08-13 設計

### コード事実 (設計前に確認)

- `update_note` は **履歴を記録しない**。履歴を記録するのは `autonomous_update_note` のみ
- ボールトの実ファイル (.md) は **CRLF行末** (実測: 代表ノート3件で110〜619の CR を含む)
- `fetch` は **生データを返し、改行正規化なし**
  → find に CRLF を含める必要が生じる罠 → **LF正規化照合 + 書き出し時に行末復元** で解決

### 設計判断

| 項目 | 決定 | 理由 |
|---|---|---|
| 操作 | operations 1〜20件・原子的 | 部分修正の典型は複数箇所。部分適用による中途半端な状態を防ぐ |
| find 一致 | ちょうど1件必須 (replace_all で明示的全置換) | 曖昧一致の誤書き換え防止 |
| revision | 必須 (update_note と同じ) | stale 防止の一貫性 |
| 不変path・review | 既存writeツールと同じ保護 | 原典保護設計の継承 |
| 履歴 | **記録する** (autonomous方式) | ユーザー判断で推奨案を選択。部分編集ほど監査が重要 |
| no-op | 拒否 | 無駄な書き込み・履歴汚染防止 |
| CRLF | LF正規化照合 + 書き出し復元 | 実ファイルCRLFへの実用対応 |
