# Orchestration

## Parallel discovery

- Packet 01 owns read-only tracing of the current app header and every action it exposes.
- Packet 02 owns read-only inventory of settings surfaces, persisted values, dialogs, and tests.
- Packet 03 owns current primary-source Obsidian reference research. It does not infer TSUZUNE code behavior.
- Packet 04 owns read-only visual, responsive, keyboard, and accessibility critique of the supplied screenshot and current styles.

## Integration policy

- The parent agent owns requirements integration, all product-code edits, tests, production update, and production TSUZUNE writes.
- Existing actions and IPC contracts are reused. Moving an entry point must not create a second implementation of the action.
- Header reduction must not hide update errors, sync state, the active Vault, or access to Settings.
- Settings information architecture may change; persisted shape and security boundaries may not change in this slice.
- No packet may add dependencies, edit production Vault content, publish Git changes, or broaden the campaign into plugin/account/cloud parity.

## Verification

The parent runs focused RED/GREEN tests, full repository gates, isolated Electron captures at 1440/900/720 CSS px, production update, installed smoke/hash/profile checks, post-restart MCP delivery checks, and one final TSUZUNE writeback.
