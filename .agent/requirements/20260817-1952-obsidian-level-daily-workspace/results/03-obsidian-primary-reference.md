# Result 03 — Obsidian primary reference

2026-08-27時点の公式資料から採用するのは配置の複製ではなく責務である。

- Ribbonは高価値commandを置く縦toolbarであり、TSUZUNEでは既存の高頻度actionとapp操作だけに限定する。
- SettingsはOptions等のcategory navigationを持ち、設定rowはtask-oriented、説明付き、可逆である。
- Vault switcherはactive root identityとsafe switchingを担う。TSUZUNEへrename／move／remove権限は追加しない。
- Sync statusはbottom status領域のlocal stateとして扱われる。TSUZUNEはGoogle接続をcloud parityやaccount systemへ拡張しない。
- top chromeはwindow/frame/tab responsibilityへ絞られ、恒常的なapp action列の根拠にはならない。

Sources:

- https://obsidian.md/help/settings
- https://github.com/obsidianmd/obsidian-developer-docs/blob/main/en/Plugins/User%20interface/Settings.md
- https://obsidian.md/help/manage-vaults
- https://obsidian.md/help/sync/messages
- https://help.obsidian.md/Obsidian%20Sync/Introduction%20to%20Obsidian%20Sync
- https://github.com/obsidianmd/obsidian-api

最強の反証は、Obsidianのshellがplugin、account、Sync、cross-platform、広いVault lifecycleを支える点である。TSUZUNEはlocal one-device contractを守り、feature-count parityは採用しない。
