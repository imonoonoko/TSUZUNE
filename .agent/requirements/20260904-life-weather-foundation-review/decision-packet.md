# Owner decision packet — LIFE Weather foundation

## decision

Whether to retire the current `one note = one always-visible light` / 90-second event-following composition as the primary artwork foundation, and authorize an isolated Living Archive Field proof before any product integration.

## options

1. **Living Archive Field proof**: keep one logical/provenance identity per note under a deterministic causal receipt, allow notes to become traceable contributions to shared material, build a persistent world-coordinate/depth-layer representation and independently integrated camera, and render the first proof with direct WebGL2. Its protocol is frozen before rendering. It does not alter product source, dependencies, production, or Git.
2. **Continue Gate 3B.5 incrementally**: retain 599 visible lights, fixed event lanes, scalar-depth projection, and WebGL2 feedback; adjust composition/material/camera further. Lowest immediate implementation change, but retains the strongest diagnosed artistic ceiling.
3. **Technology-first rewrite**: move immediately to raw WebGPU, Three.js, Rust/WASM, or a native engine. Expands rendering capability and engineering scope before proving a different artwork contract.
4. **Stop LIFE Weather**: preserve Gate 3B.5 and its evidence as research, with no further artwork or product work.

## recommendation

Choose option 1 with the verified corrections: deterministic contributor receipts, no cue-time world/camera rebase, one pre-registered blind acceptance protocol, and an unambiguous same-BrowserWindow client-area presentation with tool chrome hidden. The user feedback and live evidence point to a representation/time/world problem, not a missing language feature. Use current TypeScript data/provenance work and direct WebGL2 as scaffolding, while replacing the literal point contract, fixed score loop, event-following camera, and ordinary tool-view presentation. Keep WebGPU as a measured second backend because this PC can initialize it, not because it is newer.

## evidence and unknowns

Evidence: the current source and live prototype run stably and visibly change, but sampled frames still read as sparse white points; the vertex path is 2D plus scalar depth; history is screen-space; the score is a fixed 90-second global cycle; event pairs determine composition targets; the product route is an ordinary Canvas 2D tab. Independent artwork, rendering, and integration reviews agree that language replacement is not the first cause and that an immersive same-window surface is the smallest credible product placement. Independent adversarial verification found no P0 but required the causal, continuity, comparison, and presentation invariants now incorporated in the proof.

Unknowns: whether the contributor model will remain perceptibly personal rather than merely produce better abstract art; whether a WebGL2 world-space field meets the frame budget; whether twelve silent minutes sustain attention; whether the owner prefers a full-window same-process surface after the isolated proof. These are the vertical slice's falsifiable questions.

## reversibility and impact

Option 1 is isolated and highly reversible: the existing Gate 3B.5 remains intact as a control, no package or product boundary changes, and failure costs one bounded art proof. Adopting it later changes a major representation contract and product presentation, so product wiring remains separately gated. Option 2 is technically cheapest but risks repeated local patches. Option 3 has the highest build, maintenance, and migration impact. Option 4 has no implementation impact and ends the flagship artwork direction.

## defer cost

Deferring the decision while continuing visual tweaks has a high cost: more work accumulates on a point/event/camera structure already implicated by several rounds of feedback. Deferring all work has a low operational cost because the prototype is isolated, but postpones evidence for TSUZUNE's flagship artistic promise. A bounded option-1 proof is the lowest-cost way to distinguish an art-foundation failure from a renderer-capability failure.

## decision owner

The TSUZUNE owner. No implementation agent may authorize the representation-contract change, new dependency, product integration, production update, or Git delivery.
