# Alternatives

## Graph

### A. 全Vaultの力学グラフ

見栄えは良いが、レイアウト計算、拡大縮小、ドラッグ、密集対策が必要になる。初版では採用しない。

### B. 選択ノート中心の1-hopグラフ

選択中ノート、リンク先、バックリンクだけを表示する。既存のリンク解析を再利用でき、現在の作業に直結するため採用する。

### C. 関連ノート一覧だけ

既に右ペインに存在するため、新しい価値が小さい。グラフの代替にはしない。

## Google authentication

### A. Electron内の埋め込みブラウザ

OAuthの推奨経路ではなく、認証情報を扱う境界も複雑になるため採用しない。

### B. システムブラウザ + Authorization Code + PKCE + loopback

Windowsデスクトップアプリ向けの標準的な方式。採用する。

### C. サービスアカウント

本人の個人Driveを自然に扱う方式ではないため採用しない。

## Drive scope

### A. Drive全体の読取・書込

権限が広く、審査や利用者の不安が大きい。初版では採用しない。

### B. `drive.file`

TSUZUNEが作成または本人がTSUZUNEへ明示的に渡したファイルに限定できる。採用する。

### C. `drive.appdata`

アプリ専用の非表示領域で安全だが、ユーザーがMarkdownをDrive上で確認しにくい。同期本体には採用しない。

## Sync

### A. 常時バックグラウンド双方向同期

監視、再試行、競合、削除伝播が複雑になるため初版では採用しない。

### B. 手動双方向同期

利用者が同期前に状態を確認でき、事故範囲を小さくできるため採用する。

### C. 一方向バックアップ

最も簡単だが、別端末から戻す用途を満たしにくい。初版のフォールバックとしては有効だが、目標にはしない。
