# TSUZUNE LIFE Weather 反省点と今後の制作原則 — 2026-09-04

この文書は、観測宙域R0からGate 3B.5までの利用者実見、実装、検証、設計変更を、次の制作で同じ失敗を繰り返さないために統合した現行の反省点正本である。技術的なPASSと作品としての採用を分け、存在相理論そのものと有限な画面表現も分ける。

## 1. 最新状態

- Gate 3B.1「播種相」は、工房主の「美しくはない」で美的FAILとなった。
- 現行候補は、製品から隔離したWebGL2版 **TSUZUNE LIFE Weather Gate 3B.5「奥行きと速度連続カメラ」** である。
- 実Vault由来599ノートを、一note＝一logical identity＝一つの光として保持する。
- 発芽・回帰・合流という実資料由来の現象を最大2件重ね、捕獲、圧縮、公転、破裂、播種へ進める。
- 離散後は暗転させず、高速放出、三次元的な周回、緩い漂着によって広い星野と複数の小核へ光を受け渡す。
- 関係線、偽星、独立したprocedural fog、色分けによる分類は現行候補にない。
- 38件のmodel／renderer契約test、typecheck、構文、Codex内ブラウザのWebGL2表示は検証済みである。
- Gate 3B.2では、二つの資料現象の中点を観測重心とし、実際の現象間軸を対角方向へ投影した。長粒化は撤回し、最大粒径を縮小して中央の余白と個々のnote光を戻した。
- Gate 3B.3では、現象担当の交代を画面切替として露出していた即時観測変換を廃止した。観測中心と角度を持続状態へ補間し、現在光は点のまま、実速度の方向は通過残光だけへ接続した。残光露光も資料現象の局面に従って連続変調する。
- Gate 3B.4では、画面座標の残光とnote世界座標のflowを無変換で重ねていた座標系不一致を修正した。flowの密度・方向を現在の観測フレームへ投影し、前frameの残光も現在frameへ再投影してから移流する。
- Gate 3B.5では、目標位置だけを一次遅れ補間していたため、目標交代時に速度方向が不連続になる問題を修正した。観測中心と角度を速度状態を持つ臨界減衰系にし、現在の進行方向を保ちながら新しい目標へ曲がる。depthに基づく視差、透視倍率、粒径、輝度の差も拡大し、描画とhoverの投影式を一致させた。
- **作品としては未採用**。Gate 3B.5の工房主再判定、12分無操作、Vault因果比較、製品統合、本番反映、Git deliveryは未完了である。

## 2. いちばん大きな反省

### 技術的に成立したことを、作品が前進したことと混同した

配置、衝突回避、決定性、長時間有限性、WebGL、testがPASSしても、R0からR5まで工房主の像には届かなかった。正しく動くGraph、正しく動く局所tree、正しく動く粒子場は、どれも芸術作品であることを保証しない。

今後は次を別々のgateとする。

1. **機械gate**: 止まらない、壊れない、由来を失わない、privacyを守る。
2. **因果gate**: Vaultまたはnoteを変えると、追跡可能な理由で作品が変わる。
3. **作品gate**: 説明なしに見続けたい、本人の蓄積だと感じる、もう一度見たい。

機械gateのPASSを作品gateの代用にしない。

## 3. 失敗の系譜

| 段階 | 何が駄目だったか | 根本原因 | 残す教訓 |
|---|---|---|---|
| R0 全量Graph | 589ノート／4175リンクが矩形の配線塊になった | データを全部見せることを豊かさと誤認した | 鑑賞面に全量node／edgeを持ち込まない |
| R1 one-hop | 原子模型に見え、中心noteが本質的中心に見えた | Graphの中心性を宇宙へ化粧しただけだった | 関係線と固定中心を作品文法にしない |
| R2/R3 局所tree | 広い空間に小さな図が浮くだけだった | 可読性を優先して、宇宙全体と変化を切り落とした | Graph閲覧と受動鑑賞を同じ画面で解決しない |
| R4 星野＋link列 | 星野の中に固定Graphが残った | 宇宙背景の上へ旧Graph文法を置いた | 背景を変えても構造がnode-linkなら別作品にならない |
| R5 自律粒子場 | 動くが、本人のノートである必然が弱かった | 汎用noiseとseedが主役でVaultは参加者に留まった | ノート差は見た目だけでなく出来事と力学の原因にする |
| 初期LIFE Weather | ただ漂い、時間とともに変化が乏しくなった | 局所運動が場へ蓄積されず、次の運動へ返らなかった | 履歴を描画残像だけでなく次の力学へfeedbackする |
| 線・輪郭・白いモヤ | 線がnodeから伸び、輪郭とmosaic fogがチープだった | 意味のないprocedural装飾で情報不足を埋めた | 可視物にはnote、出来事、通過履歴のいずれかの由来を要求する |
| ノート別の色 | 個性より分類色に見え、作品全体が散った | 差異を最も簡単な色相へ畳み込んだ | 個性は応答、速度、境界、脈動、痕跡へ分散する |
| 4,792 visual fragments | 虫や原子模型のようで「キモい」印象になった | 一noteの存在感を装飾片の多さと誤認した | 一note一光を基準とし、分裂表現は明示採用まで戻さない |
| 高速な捕獲・離脱 | 現象を見届ける前に次へ切り替わった | 90秒へ候補とlaneを詰め込みすぎた | 一現象を最低30秒とし、変化の速さより読める時間を守る |
| 墨彩画reset | 面は生まれたが宇宙感を失った | 通過履歴を画面の主成分へ持ち上げすぎた | 履歴は力学に強く、画面では局所的で希薄にする |
| afterimage暗転 | 離散後に作品の生命が途切れた | 余白を「光がなくなる時間」と設計した | 余白にも弱い星野を保ち、離散を次の構図への播種にする |

## 4. 制作過程の反省

### 4.1 実装前の像合わせが弱かった

「宇宙」「量子」「太陽系」「煙」といった比喩を、運動、時間、材質、構図へ分解する前に実装へ進んだ。そのため、言葉としては合っていても、出来上がると別物になる往復が続いた。

今後は実装前に一枚の制作契約を固定する。

- 30秒後に何が変わっているか。
- 主役、余白、背景は何か。
- 何が現れたら即FAILか。
- その光や形はどのVault事実に由来するか。
- 参考作品のどの構造を学び、どの表層を真似しないか。

### 4.2 参考作品の研究が遅かった

Tendrilsを全編とeditorまで観察して初めて、魅力が「煙の見た目」ではなく、共有場、履歴feedback、spawn、材質遷移、keyframeによる演出された創発の組合せだと分かった。最初からこの分解を行うべきだった。

今後、基準作品は静止画や冒頭数秒で判断しない。全時間構成、制作情報、editor、作者説明を確認し、基礎力学、時間構成、材質、操作、音響を分けて記録する。

### 4.3 違和感を追加エフェクトで埋めた

線、輪郭、煙、色、衛星片を足すほど、Vaultとの因果と作品の焦点が弱くなった。問題が「構図」「時間」「由来」にある時、shader装飾を増やしても解決しない。

今後の修正順は次とする。

1. 不要な表現を削る。
2. 主役と余白を直す。
3. 時間構成を直す。
4. Vault因果を直す。
5. 最後に材質を調整する。

### 4.4 静止画と短時間確認に頼りすぎた

一枚の良いframeは、時間とともに停滞すること、急に暗くなること、同じ構図を反復することを隠す。作品の評価対象はframeではなく変化の連続である。

今後は少なくとも、開始、30秒、60秒、90秒の証拠と、途中を飛ばさない連続鑑賞を分ける。最終候補では12分無操作と翌日再訪を残す。

### 4.5 利用者へ見せる導線が不安定だった

Codex内ブラウザを開いた直後に閉じる、別の場所へ表示するなど、工房主が見られない状態があった。作品開発では表示できたことより、同じ版を利用者が自分の時間で鑑賞できることが重要である。

今後は既存のCodex内ブラウザtabを再利用し、明示的に閉じず、再読込後にURLと版を確認して開いたまま渡す。

### 4.6 状態文書が追いつかなかった

当時、requirement内の最新planはGate 3B.1を指す一方、`discussion_log.md`の途中にはR5をcurrentとする歴史的文言が残り、ルート`PLAN.md`と`PROJECT_STATUS.md`もR2を現行候補としていた。現在のrequirement planはGate 3Cへ同期したが、共有入口の歴史的表記は別scopeとして残る。履歴保存は必要だが、`current`という語が複数時点に残ると再開者を誤誘導する。

今後は、一つのcurrent state ownerだけを明示し、歴史的節は`historical`と表示する。共有入口文書は、他作業のdirty変更を統合できる安全な時点でGate 3Cへ同期する。

## 5. 存在相理論との関係で守ること

- 世界と経験は分類、命名、記録より先にある。ノートや画面は局所的な分節と観測表現である。
- 存在相そのものをGraph、経路、二次元格子、粒子simulationへ同一化しない。
- 近さ、明るさ、大きさ、所属clusterを、真の関係、価値、重要度、同一性として扱わない。
- 表示されないnoteを不存在または低価値とみなさない。
- link欠落を関係の不在と断定しない。
- ノート差を単一scoreへ畳み込まない。内容、時点、link、構造、境界、履歴、残留、再同定、不確実性を別軸のまま作用させる。
- 作品の変化にはsource、使用軸、選定理由、欠落、時点を制作情報から辿れるようにする。
- AIが作るまとまりやideaは観測候補であり、人間の採否なしに知識世界の事実へ昇格させない。

## 6. 次回からの制作原則

1. **作品命題を一文で固定する。** 今回は「TSUZUNEが観測してきた知識の生が、核、星野、再結合へ変わり続ける」。この命題に寄与しない機能は足さない。
2. **一つのgateで一つの美術仮説を検証する。** 同じ仮説を支える複数parameterは同時変更してよいが、色、音、camera、AI解釈を別目的で混ぜない。
3. **一note一identityを守る。** 一note一光を既定とし、装飾的な分裂や偽particleを使わない。
4. **由来のない像を足さない。** 光はnote、力は観測された資料現象、ガスは通過履歴から作る。
5. **構図と時間をshaderより先に直す。** 主役、余白、密度差、転換、余韻を低機能な白黒版で成立させる。
6. **光量を保存する。** 消散は消滅ではなく、別尺度の星野、次の核、履歴へ受け渡す。ただし全画面の一様増光にはしない。
7. **静けさを停止にしない。** 見かけ上静かな時も、次の変化へ向かう弱い勾配と複数時間尺度を保つ。
8. **比較でVault因果を示す。** same Vault／same seed、daily seed、note差替え、time／content／link／structure／phase ablationを作品gateとは別に確認する。
9. **工房主の不採用を最上位証拠にする。** testが緑でも「違う」「チープ」「キモい」「見続けたくない」が出た版は歴史化し、装飾で延命しない。
10. **製品化を急がない。** 90秒、12分、翌日再訪の作品gateを通るまで、本番UI、音楽、共有、WebGPUへ広げない。

## 7. 現在残っている問題

### P0 — Gate 3C候補は作品として未採用

Evidence: Gate 3Cは機械・実画面・独立静的検証済みだが、工房主の最終三問は未回答。

Impact: 製品統合へ進む根拠がない。

Fix: 現在開いているGate 3Cを連続鑑賞し、「自分のノートだからこうなった」「90秒見たい」「蓄積後にまた見たい」を判定する。

Verification: 工房主三問。いずれか否なら次の美術仮説を一つだけ選ぶ。

### P1 — Vault因果の見た目がまだ弱い可能性

Evidence: source-backed eventとablationは機械的に確認したが、説明なしで本人固有と感じられるかは未確認。

Impact: 高品質な汎用particle artworkに留まる。

Fix: 同じseedで一note差替えと異なるVault conditionを並べ、変化が局所的かつ追跡可能かを見る。

Verification: Gate 3Bの4比較と工房主判定。

### P1 — 高密度核が白い塊へ崩れる瞬間

Evidence: Gate 3B.1のseeding相で、画面端の核が局所的に飽和するframeを確認した。

Impact: 宇宙の局所現象ではなく描画破綻または白いblobに見える。

Fix: 次の美術調整を行う場合は、核の最大露光、画面端投影、近接時の粒径のどれか一つを測って変更する。

Verification: 同じ時間帯を変更前後で連続比較し、星の個体感と局所強度を両立する。

### P1 — 長時間構成は未検証

Evidence: 現行scoreは90秒。12分無操作、短周期反復、長時間飽和、翌日再訪は未確認。

Impact: 短いdemoとして良くても、高級なスクリーンセーバーにはならない。

Fix: Gate 3Cの90秒作品が採用された後だけ、12分無操作と翌日再訪の長時間gateへ進む。

Verification: 12分無操作、構図反復、停止、収束、飽和の観察と翌日再訪。

### P2 — 正本ドリフト

Evidence: requirementの`plan.md`はGate 3Cをcurrentとするが、ルート`PLAN.md`／`PROJECT_STATUS.md`はR2、`discussion_log.md`中盤はR5をcurrentと記す歴史的箇所が残る。

Impact: 後続が不採用版を再開する。

Fix: 他作業のdirty変更を保全できる統合時点で、共有入口を現行planへ同期し、歴史節の`current`を明示的にhistorical化する。

Verification: `rg`でactive／current／次の一手を検索し、現行候補がGate 3Cの一箇所へ収束していることを確認する。

### Gate 3Cで追加した再発防止

通過履歴を閾値で二値的に持ち上げると、由来が正しくても濃部が平坦な灰色blobへ崩れた。履歴を可視化する時は、追加の星雲や輪郭ではなく、連続露光曲線で暗部の透過率へ変換し、密度稜線で局所化する。形成期と90秒相当の種蒔き期を同じrunで見て、局所現象が全画面washへ広がらず黒へ戻ることを確認する。

## 8. 次の一手と停止線

次の一手は新規実装ではなく、Gate 3Cの工房主鑑賞判定である。Gate 3B.5の奥行きと速度連続cameraに加え、光の通過が局所の闇を開き、履歴が解けると広い黒へ戻る持続感を確認する。3Cが採用されなければ、見えた問題を同じ分類へ戻し、複数の装飾案を同時投入しない。

音楽、YouTube、AIによる意味生成、WebGPU、3D camera、製品統合、本番反映、Git deliveryはHeldのままとする。作品gateを通る前に、機能追加で完成感を作らない。
