# 観測宙域 MVP Alternatives（R5）

## A. 全量Graphをcameraで巡る

- 状態: **却下**
- 実見: 589ノート／4175リンクが矩形の配線塊になり、global座標の切り出しは画面端へ偏った。
- 結論: opacityや速度では直らず、描画単位そのものが鑑賞目的に合わない。

## B. rootのone-hopを放射状に描く

- 状態: **却下**
- 実見: 数本の線が中心から均等に伸びる原子模型となり、rootが本質的中心であるように見えた。

## C. 最大9星の局所treeだけを見せる

- 状態: **利用者実見で却下**
- 実見: hairballは消えたが、広い空白に小さなnode-link図だけが残り、宇宙や変化する集団の予感が失われた。

## D. 実ノートの星野から一つの明示link列を焦点化する

- 状態: **利用者実見で却下**
- 形: 最大72個の実ノートをfieldへ広げ、最大3列×6星を候補として保持する。同時に見せるのは1列／5線まで。9秒ごとに焦点を移し、3focus後に全景を再構成する。
- 実見: 星野の上に別の固定された小Graphを載せただけに見え、粒子そのものが集散する空間にならなかった。

## E. 実ノート粒子の自律的な集散

- 状態: **R5開発source MVP採用**
- 形: 最大72個の実ノート粒子を一枚のCanvasへ置き、移動する一時的な潮目、部分参加、近距離反発、漂流、減衰、境界復元によって集合・離脱・再編を連続的に生む。
- 理由: 線、固定中心、固定群数、sceneを使わず、空間全体と時間変化を主役にできる。名称とWiki linkは運動へ使わず、見える群を真の意味clusterと断定しない。

## F. LLM／embeddingによるLiving Cosmos

- 状態: **Future／Held**
- 可能性: 明示link以外の暫定的な集団、問い、仮説候補を生成・解散する。
- 再開条件: R5が実Vaultで鑑賞価値を持ち、Source／Observation／Proposal、不確実性、provenance、時点、利用者採否、自律書込み禁止を独立して設計・検証できた時。

## Decision

現MVPはEだけ。A〜Dの失敗を設計履歴として残し、Fのruntimeや依存を先回りして作らない。
