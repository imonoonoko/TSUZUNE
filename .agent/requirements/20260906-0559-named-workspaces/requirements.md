# ワークスペース保存・復元 — 要件

設計日: 2026-09-06 JST。利用者は未実装候補の調査後、「設計に進んで」「ワークスペース保存・復元から具体化」を選択した。

## 目的と今回の完了境界

調べものや執筆に使うノートの組合せを名前で保存し、別の作業やアプリ再起動を挟んでも、前の作業へ戻れるようにする。本人用・Windows一台・現在のVault内で使う。

今回の成果は、保存内容、操作、失敗時の挙動、実装箇所、受入ケースを揃えた設計である。製品コードの実装、本番導入、Git公開は含まない。実行状態は [PLAN.md の Current Decision](../../../PLAN.md#current-decision) が所有する。設計の詳細は [design.md](design.md)、実装時の受入基準は [acceptance.md](acceptance.md) を参照する。

CEO-01が設計と統合を担当する。define-requirements、ai-coding-operator、Ponytailを使い、既存状態と保存経路の読取調査、公式公開仕様の読取確認だけを一時Agentへ委譲する。既存の未commit変更を保持する。状態管理は既存PLANを使うPlannedとし、別の管理台帳は作らない。

## 成功条件

1. 保存・読込・同名更新・削除・再起動・Vault切替の期待動作と保存対象が一意に分かる。
2. 未保存本文、外部編集、消えたファイル、設定の破損・保存失敗で、利用者のデータと元の作業を失わない境界が定義される。
3. 既存実装を再利用した変更箇所と、各要件を判定できる受入ケースが対応する。設計検査と製品動作の検証を区別する。

## 用語と利用場面

**ワークスペース**は、現在のVaultで開いているタブと周辺の表示状態の組合せ。「調査」「執筆」などの名前で明示保存する。ノート本文のコピーや過去版ではない。

**前回の作業状態**は、名前を付けずに自動保存する直近一件の配置。次回、同じVaultを開いたときに使う。名前付きワークスペースとは別に管理し、日々の操作で名前付き保存を上書きしない。

- 調査用のノート数件とGraphを開き「調査」と保存する。別のノートで執筆した後、「調査」を読み込み、元のタブ構成と選択中だったタブへ戻る。
- アプリを通常終了し、次回は前回のタブ構成で再開する。本文はその時点のVaultの最新保存内容を読む。
- 保存後にノートが移動・削除されていても、開けるタブへ戻り、開けなかった対象を確認できる。

## 保存するもの

| 状態 | 初回仕様 |
|---|---|
| タブ | ノート、添付、バックリンク専用タブ、Global Graphの種類と順序。ファイルはVault相対path |
| 選択中のタブ | 同じpathを開いた複数タブも区別できる配列位置 |
| 選択中ノートの表示 | 編集／プレビュー／Local Graph。ほかのノートへ切り替えた後の表示規則は既存どおり |
| 左サイドバー | 開閉、ファイル／検索／ブックマークの選択、検索文字列 |
| 右サイドバー | 開閉、アウトライン／リンク／バックリンク／時間の表示種別。各表示内のスクロールや見出し選択は含めない |
| 名前付き保存の情報 | 名前、保存日時。保存内容の一覧はタブから表示 |

本文、未保存draft、変更履歴、検索結果本文、MRU履歴、カーソル・スクロール、展開folder、ダイアログ、入力途中のcapture、window位置、Graphの座標・物理配置は保存しない。Graphのフィルタ等は既存の共通設定を使う。

サイドバー幅は現在のCSS配置に従う。幅変更機能、分割pane、Obsidian workspaceファイルのimport/export、別Vaultへの自動切替、cloud同期、MCP操作の追加は対象外。廃止済みの「知識の時間」専用workspaceや観測宙域は復活させない。

## 操作の形

常設の新パネルは作らず、既存コマンドパレットに「ワークスペースを保存」「ワークスペースを開く」を追加し、同じ小さなダイアログを使う。新しい固定ショートカットは割り当てない。

```text
ワークスペース

現在の配置を保存
名前  [調査                    ] [保存]

保存済み
調査   4タブ・9月6日 06:00       [開く] [削除]
執筆   2タブ・9月5日 22:10       [開く] [削除]

                            [閉じる]
```

同名ならボタンを「この名前で更新」に変え、押した操作が既存配置の置換になると示す。削除は対象名と「ノートは削除されません」を確認画面に表示する。一覧は保存日時の新しい順。同じ日時は名前順とする。

読込前に未完了capture等の別ダイアログがある場合はその既存操作を先に完了／キャンセルする。読み込み中は操作を重ねられず、失敗なら元の画面で理由を知らせる。成功時は「調査を開きました」。欠落があれば「3タブを開きました。1件は見つかりません」と対象pathを展開できる形で知らせる。

## 比較と採用理由

| 案 | 判断 |
|---|---|
| 現状の最後のノート復元だけを継続 | 最小だが、利用者が選択した複数タブの作業再開を満たさない |
| 既存タブ＋既存settingsへ配置を保存 | 初回の設計案。本文の正本を増やさず、既存操作と保存保護を再利用できる |
| pane分割、幅変更、全表示設定、全tabの編集bufferまで保存 | 初回対象外。作業セットの再開を越える変更とデータ保護責務が増える |

この仕様の使いやすさは未確認。実装後、本人の二つの実作業を一往復する確認で、復元対象の不足を判断する。使いやすさや操作時間の改善を設計だけで実証したとはしない。
