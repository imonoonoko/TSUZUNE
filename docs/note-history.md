# 通常ノートの版履歴・差分確認・復元

## 目的と対象

デスクトップで通常ノートを編集した際、保存前の本文を残し、現在の本文との差分を確認して過去版へ戻せるようにする。Markdown正本を維持し、新しいDB・依存・常駐処理は追加しない。

- アプリのノート保存（自動保存を含む）、プロパティ編集、未リンク言及のリンク化、過去版の復元で本文が変わる時に旧本文を記録する。同一本文の保存では版を増やさない。
- 保存先はVault内の隠し領域 `.tsuzune/note-history/`。旧 `50_履歴` とは独立し、通常の検索・Graph・MCPのノート集合に混ぜない。
- MCP・Drive・外部エディタによる更新を監視して記録する機能ではない。MCPの履歴なし更新契約は維持する。
- 対象は通常のMarkdownノート。`40_情報源`、`50_履歴`、隠し領域は対象外。
- 履歴はノートのパスごとに保持する。名前変更・移動前の履歴は旧パスに残り、新しいパスの一覧へは引き継がない。名前変更・移動に伴う内部リンクの一括書換は記録対象外。
- 履歴の自動削除や既存監査履歴の移行は行わない。変更保存ごとに本文全体を残すため、保存容量は増える。Vaultを退避する場合は隠し領域も含めて保全する。

## 利用操作と安全条件

1. ノートの「版履歴」を開く。未保存編集は通常の競合検査付き保存を完了してから開く。失敗したら現在の編集を保ち、履歴操作へ進まない。
2. 保存前の版を選ぶ。保存日時・本文・現在との差分（追加／削除）を表示する。本文をHTMLとして実行しない。
3. 「この版に復元」で対象版を確認し、現在の保存済み本文に一致する場合だけ復元する。復元直前の本文も版として保存するため、復元を戻せる。
4. 外部変更、Vault切替、履歴の破損、履歴保存失敗では上書きしない。明示的な強制復元は提供しない。

各版は元のMarkdown本文をそのまま保存し、ファイル名の内容hashで読取時に整合性を確認する。新機能の導入前の本文や未保存のキー入力を遡って復元することはできない。

### 件数・容量・日時と対象説明

版履歴画面のパス直下に、このパスの過去版の件数、保存本文の合計バイト数（B）、最古・最新の履歴保存日時を表示する。件数は一覧の版数、容量は既存metadataのsize合計、日時はsavedAtの最小・最大で、同時刻の別版も数える。0件なら「0件・0 B」「日時なし」。現在本文・管理ファイル・一時/未知ファイル・filesystem管理領域を含まず、Vault全体のディスク使用量や全版の検証結果ではない。

表示は画面を開いた時点の取得結果であり、再度開くと再取得する。取得失敗を0件として扱わない。表示日時は元本文の執筆日時ではなくsnapshotの保存日時。同じパスを再利用した場合は以前の版が並び得る。

保持期間と件数に上限はなく、自動整理も行わない。画面には保存対象と、改名・移動前の履歴が旧パスに残ることも表示する。

差分は行単位で、CRLFと末尾改行なしも区別する。共通の先頭・末尾は3行ずつ表示する。中間部分の比較が25万セルを超える場合は変更範囲全体をまとめて表示し、表示上限は2,000行／15万文字。簡略表示・省略時は画面内へ明示し、選択した版の本文は省略しない。
