# テンプレートと情報の鮮度

更新日: 2026-08-10

## テンプレートを使う

Vaultに`90_テンプレート`フォルダを作り、その中へ通常のMarkdownノートを置きます。入れ子フォルダも使えます。

```markdown
---
review_after: 2026-09-01
---

# {{title}}

作成日: {{date}}

## 要点

## 次にすること
```

左サイドバーの選択欄から雛形を選び、`テンプレートから作成`を押します。新しいノート名を入力すると、現在選択しているフォルダへ新規ノートを作ります。雛形原本は変更しません。

使えるplaceholderは次の4つです。

| placeholder | 展開例 |
|---|---|
| `{{title}}` | 入力したノート名 |
| `{{date}}` | `2026-08-09` |
| `{{time}}` | `14:30` |
| `{{datetime}}` | `2026-08-09T14:30` |

未知のplaceholderは勝手に削除せず、そのまま残します。

## Markdownを知らなくても記録できる入口

対象利用者はMarkdown記法を知らないことを既定とします。Markdownは保存形式として残しますが、日常操作では記法、template path、placeholder、frontmatterを手入力させません。

初期テンプレートは次の2種類に絞ります。

### デイリーノート

- 常設ボタン: `今日のノート`
- 入力欄: 今日やったこと、気づき、自由メモ、次にすること
- 既定保存先: `02_デイリー/YYYY-MM-DD.md`
- 同日のノートがあれば新規作成せず、そのノートを開く
- 「次にすること」は複数行で入力し、1行ずつMarkdown checkboxへ保存する

### アイデアノート

- 常設ボタン: `アイデアを追加`
- 必須入力: タイトル、アイデア本文
- 任意入力: なぜ気になったか、関連プロジェクト、自由メモ、次の一歩
- 既定保存先: `01_受信箱/アイデア/<タイトル>.md`
- 関連プロジェクトは既存ノートを選び、アプリがWikiリンクへ変換する
- 「次の一歩」は複数行で入力し、1行ずつMarkdown checkboxへ保存する

左サイドバーの`今日のノート`と`アイデアを追加`から、項目名付きフォームを開けます。通常の`ノート`もアプリ内フォームで作成し、名前に加えて改行、空行、インデントを含む自由な本文をそのまま入力できます。見出し、太字、箇条書き、チェック項目は書式ボタンで挿入でき、関連ノートはVault一覧から選ぶだけでWiki linkになります。

TSUZUNEが生成した定型Daily／Ideaは、表示画面の`内容を編集`から同じフォームへ戻せます。parse後に同じMarkdownを再生成できる場合だけフォーム編集を許可するround-trip guardを使います。未知の見出しや自由な構造を追加したMarkdownは、フォーム保存で内容を消さないため自動変換せず、通常の`編集`からMarkdownソースをそのまま扱います。定型ノートではソース編集を`Markdownソース`という副操作として残します。

一般ノートの作成フォームとMarkdown編集欄には、見出し、太字、箇条書き、チェック項目の最小書式ボタンがあります。選択文字へ標準Markdownを挿入するだけで、独自リッチテキスト形式は作りません。関連ノートの挿入では、表示名として安全に使える選択文字だけをaliasへ使い、改行や`|`などを含む選択は壊れない通常Wiki linkへ退避します。保存後は従来どおり検索、Wiki link、Graph、MCP、外部エディタで利用できます。

同名のアイデアや作成失敗ではフォームを閉じず、入力内容と画面内エラーを残します。フォームへ入力がある状態でアプリを終了するときも確認し、保存前の内容を黙って捨てません。

## 最終更新と鮮度を見る

ファイル一覧には各Markdownの最終更新日を短く表示します。カーソルを合わせると正確な日時、経過日数、状態を確認できます。検索結果と開いているノートのfooterにも同じ情報を表示します。

| 状態 | 初期ルール | 意味 |
|---|---|---|
| 最近更新 | 30日未満 | 最近変更された |
| 要確認候補 | 30日以上 | 内容を見直す候補 |
| 古い可能性 | 90日以上 | 現在も有効か優先的に確認する候補 |
| 再確認期限超過 | `review_after`を超過 | 明示した再確認日を過ぎた |

この表示は真偽判定ではありません。長期間更新されていない普遍的な知識が誤りになるわけではなく、最近更新された情報が正しい保証もありません。

明示的な再確認日を付けたい場合は、frontmatterへ次のように書きます。

```yaml
---
review_after: 2026-09-01
---
```

初版は`YYYY-MM-DD`だけを解釈します。ノート本文やfrontmatterを鮮度機能が自動的に書き換えることはありません。
