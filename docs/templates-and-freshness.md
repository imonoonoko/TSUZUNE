# テンプレートと情報の鮮度

更新日: 2026-08-10

## テンプレートを使う

最初から`今日のノート`、`アイデアメモ`、`学びメモ`、`プロジェクトメモ`の4種類が内蔵されています。これらはメモリ上の候補なので、Vaultを開いただけで`90_テンプレート`へファイルを作りません。同じpathの実ファイルがあれば、内蔵候補より優先されます。

```markdown
---
review_after: 2026-09-01
---

# {{title}}

作成日: {{date}}

## 要点

## 次にすること
```

左サイドバーの選択欄から雛形を選び、`テンプレートから作成`を押します。作成画面は挟まず、同名衝突を避けたノートを作って通常の編集画面で開きます。`今日のノート`は日付名で`02_デイリー`へ、`アイデアメモ`は`01_受信箱/アイデア`へ保存し、それ以外は現在選択しているフォルダへ保存します。雛形原本は変更しません。

`テンプレートを追加`を押すと、`90_テンプレート/新しいテンプレート.md`を作って通常の編集画面で開きます。本文を自由に直し、通常の`名前変更`で用途が分かる名前へ変えます。追加したMarkdownは自動的に選択欄へ現れ、入れ子フォルダも使えます。

使えるplaceholderは次の4つです。

| placeholder | 展開例 |
|---|---|
| `{{title}}` | 入力したノート名 |
| `{{date}}` | `2026-08-09` |
| `{{time}}` | `14:30` |
| `{{datetime}}` | `2026-08-09T14:30` |

未知のplaceholderは勝手に削除せず、そのまま残します。

## Markdownを知らなくても記録できる入口

対象利用者はMarkdown記法を知らないことを既定とします。Markdownは保存形式として残しますが、日常操作では記法、template path、placeholder、frontmatterを手入力させません。

日常用の入口も、専用ボタンではなくテンプレート選択へ集約します。

### デイリーノート

- 選択肢: `今日のノート`
- 既定保存先: `02_デイリー/YYYY-MM-DD.md`
- 同日のノートがあれば新規作成せず、そのノートを開く
- 新規作成後は見出し入りの通常編集画面で、そのまま自由に書く

### アイデアノート

- 選択肢: `アイデアメモ`
- 既定保存先: `01_受信箱/アイデア/アイデアメモ.md`
- 同名なら`アイデアメモ 1`、`アイデアメモ 2`のように安全な空き名を使う
- 新規作成後は見出し入りの通常編集画面で、題名も本文も自由に直せる

左サイドバーの`ノート`は、`無題のノート`（同名なら連番）を即座に作って通常編集画面で開きます。作成モーダルへ同じ内容を二度入力する必要はありません。見出し、太字、箇条書き、チェック項目は書式ボタンで挿入でき、関連ノートはVault一覧から選ぶだけでWiki linkになります。

TSUZUNEが生成した定型Daily／Ideaは、表示画面の`内容を編集`から同じフォームへ戻せます。parse後に同じMarkdownを再生成できる場合だけフォーム編集を許可するround-trip guardを使います。未知の見出しや自由な構造を追加したMarkdownは、フォーム保存で内容を消さないため自動変換せず、通常の`編集`からMarkdownソースをそのまま扱います。定型ノートではソース編集を`Markdownソース`という副操作として残します。

Markdown編集欄には、見出し、太字、箇条書き、チェック項目の最小書式ボタンがあります。選択文字へ標準Markdownを挿入するだけで、独自リッチテキスト形式は作りません。関連ノートの挿入では、表示名として安全に使える選択文字だけをaliasへ使い、改行や`|`などを含む選択は壊れない通常Wiki linkへ退避します。保存後は従来どおり検索、Wiki link、Graph、MCP、外部エディタで利用できます。

新規作成前には現在の編集内容を保存し、保存できなければ作成処理を始めません。作成失敗時も現在開いているノートを維持してエラーを表示します。

## 最終更新と鮮度を見る

ファイル一覧には各Markdownの最終更新日を短く表示します。カーソルを合わせると正確な日時、経過日数、状態を確認できます。検索結果と開いているノートのfooterにも同じ情報を表示します。

| 状態 | 初期ルール | 意味 |
|---|---|---|
| 最近更新 | 30日未満 | 最近変更された |
| 要確認候補 | 30日以上 | 内容を見直す候補 |
| 古い可能性 | 90日以上 | 現在も有効か優先的に確認する候補 |
| 再確認期限超過 | `review_after`を超過 | 明示した再確認日を過ぎた |

この表示は真偽判定ではありません。長期間更新されていない普遍的な知識が誤りになるわけではなく、最近更新された情報が正しい保証もありません。

明示的な再確認日を付けたい場合は、frontmatterへ次のように書きます。

```yaml
---
review_after: 2026-09-01
---
```

初版は`YYYY-MM-DD`だけを解釈します。ノート本文やfrontmatterを鮮度機能が自動的に書き換えることはありません。
