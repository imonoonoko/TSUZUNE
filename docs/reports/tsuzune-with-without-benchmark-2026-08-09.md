# TSUZUNEあり／なし ベンチマーク

実施日: 2026-08-09

対象: Temporal Memory Lite M5 Context Compiler
判定: PASS（固定課題では品質改善、Context構築には約150msの追加コスト）

## 結論

同じ3件の起点ノートを人手で渡す場合と、TSUZUNEが時間・再確認期限・出典を解決してContextを組み立てる場合を比較した。

| 指標 | TSUZUNEなし | TSUZUNEあり | 差 |
|---|---:|---:|---:|
| 固定4問の厳密正答 | 1/4 | 4/4 | +3問、4倍 |
| State Note → Source一致 | 0/3 | 3/3 | 0% → 100% |
| Context構築median | 0.021 ms | 149.685 ms | +149.664 ms |
| Context構築p95 | 0.031 ms | 173.339 ms | +173.308 ms |
| 現在Context | 7,391文字／3ノート | 33,412文字／24ノート | 4.52倍／8倍 |
| 過去Context | 7,391文字／3ノート | 3,585文字／6ノート | 0.49倍／2倍 |
| 過去Contextの時間未指定本文 | 3件 | 0件 | 3件除外 |
| 解決済み出典（現在／過去） | 0／0 | 6／3 | +6／+3 |

TSUZUNEありは、現在については根拠を増やすためContextが大きくなり、過去については後から書かれた時間未指定本文を除外するため約半分になった。単に情報量を増やす処理ではなく、質問時点に応じて増減させている。

## 比較定義

- `TSUZUNEなし`: 同じ3件の起点Markdown本文だけを渡す。空入力やモデルの一般知識だけではない。
- `TSUZUNEあり`: 同じ3件を起点に、本番Vaultから時間、有効期間、再確認期限、出典を解決する。
- 現在時点は2026-08-09、過去時点は2026-07-22に固定した。
- 品質値は2026-07-31の独立した新規回答者による固定4問blind評価を再利用した。
- 性能値は現在の本番Vaultを読み取り専用で使い、20回warm-up後に200回測定した3 trialの中央値である。

## 性能実測

環境はWindows x64、Node.js v22.17.1、Intel Core i7-13700F（16 core／24 logical processor）。入力snapshotは247ファイル、9,397,940 bytesだった。

| Trial | TSUZUNEなし median／p95 | TSUZUNEあり median／p95 |
|---|---:|---:|
| 1 | 0.013／0.016 ms | 148.434／166.104 ms |
| 2 | 0.021／0.048 ms | 154.161／175.514 ms |
| 3 | 0.021／0.031 ms | 149.685／173.339 ms |

TSUZUNEありは相対値では約7,128倍だが、比較元が3文書の文字列連結だけで約0.02msのため、この倍率は実用上ほぼ意味を持たない。判断に使うべき値は約150msという絶対追加時間である。これはAI応答の秒単位時間より小さい一方、現在の実装に検索最適化余地があることは示す。

## 言えること／言えないこと

言えること:

- この固定課題では、TSUZUNEの時間対応Contextにより厳密正答が1/4から4/4へ改善した。
- 出典追跡は0/3から3/3へ改善した。
- 本番VaultのContext構築＋安全分析にはmedian約150msかかった。
- 過去時点では、時間未指定の後日本文を落とし、Context文字数も減らした。

言えないこと:

- モデル本体の一般知能が4倍になったとは言えない。
- あらゆる質問で同じ改善率になるとは言えない。
- 今回はVault scan、MCP通信、AI生成、UI描画、ノート入力の人手を性能値へ含めていない。
- 2026-07-31の品質評価と2026-08-09の性能snapshotは別時点なので、1文字当たり正答率のような合成指標にはしない。
