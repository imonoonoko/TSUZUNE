# Security Policy

## Reporting a vulnerability

Security vulnerabilities, leaked credentials, and privacy-sensitive findings should not be posted in a public Issue.

Use [GitHub private vulnerability reporting](https://github.com/imonoonoko/TSUZUNE/security/advisories/new) instead. Include the affected version or commit, reproduction steps, expected impact, and any safe evidence needed to verify the report. Do not attach a real Vault, OAuth token, credential file, or other personal data.

This is a personal project maintained on a best-effort basis, so no response-time SLA is promised. A verified issue will be addressed before its details are made public when practical.

## Supported versions

Security fixes target the latest public source and the newest GitHub Release. Older releases are not supported after a replacement is published.
